# Deload Suggestions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Suggest an easy week at the right time, run a 7-day deload week with lighter advice and pre-fill, and keep that week's sessions from distorting "Last time", progression advice and stall detection.

**Architecture:** A new pure module `public/deload.js` owns the rules (when to suggest, whether a deload is active, the lighter weight and set count, the stalled-lift rule that Coach will share). The deload state lives in `settings.deload`; workouts saved inside the window carry `deload: true`. Today gets a suggestion/active banner; the exercise card swaps its advice for a deload line.

**Tech Stack:** plain ES modules, no build; Node test runner (`npm test`), Playwright harness (`tests-ui`).

**Spec:** `docs/superpowers/specs/2026-10-25-deload-design.md`

## Global Constraints
- Windows, files are CRLF in git (autocrlf). Edit with the Edit/Write tools or a small Node patch script written with the Write tool. **Never put a regex, `\b` or `\n` inside a shell heredoc** (backslashes get eaten or become control characters). Check with `grep -c $'\x08'` over the files you touched.
- Every visible string needs an Arabic entry in `public/lang-ar.js` (`npm test` lists what is missing). No glued strings: `t("... {n}", {n})`. Digits 0-9, Latin units. Targets 44px, text 12px minimum.
- Constants: `DELOAD_DAYS = 7`, `DISMISS_DAYS = 28`, `COOLDOWN_DAYS = 42`, `STREAK_WEEKS = 6`, `STALLED_LIFTS = 3`, `SET_FACTOR = 0.6`, `WEIGHT_FACTOR = 0.9`.
- Ruling (refines the spec): `settings.deload.end` may be as early as the day before `start`; that value means "cancelled on its first day" and the deload is not active. `start` is kept either way (it drives the 42-day cooldown).
- Nothing is ever blocked and no existing number changes for people who never start a deload: with no `settings.deload` every function returns today's behaviour.
- Round-trip rule: the settings snapshot parser, `store.saveSettings`, `settingsDoc`, `cleanSettings`, and for workouts the explicit body object in `store.save` plus `cleanWorkout` must all carry the new fields.
- Bump `VERSION` in `public/sw.js` (check the file; v46 is live at the time of writing, so `iron-log-v47`) and add `/deload.js` to `APP_SHELL`. Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus
- The window arithmetic: first day, last (7th) day, ended early, cancelled on day 1, a month boundary, a viewed date other than today.
- A workout edited on a past date outside the window must not keep or gain `deload`; one saved inside it must gain it; old workouts without the field are untouched.
- Cooldown and dismissal cannot be bypassed by reloading; `dismissedUntil` in the past does nothing; junk dates in `settings.deload` behave as unset.
- `stalledLifts` agrees with the Coach rule it replaces on the existing tests, ignores bodyweight entries (`bw: true`), warm-ups, drop sets and deload workouts, and merges exercise names case-insensitively.
- During a deload "Last time" and the lines under it use the last NORMAL session; after the deload the advice continues from the pre-deload numbers.
- Bodyweight and hold exercises never get a weight in the deload line; an exercise with no history gets no deload line.
- Arabic and RTL for both banners and the deload line.

### Task 1: The deload module

**Files:**
- Create: `public/deload.js`, `tests/deload.test.js`
- Modify: `public/sw.js` (APP_SHELL only)

**Interfaces:**
- Imports: `addDays`, `e1rm` from `./achievements.js`; `workingSets` from `./progression.js`.
- Produces: the constants above; `cleanDeload(obj) -> {start?, end?, dismissedUntil?}`; `activeDeload(deload, today) -> {start, end, day} | null`; `deloadDate(date, deload) -> boolean`; `stalledLifts(workouts) -> string[]`; `suggestDeload({deload, today, streakWeeks, stalled}) -> null | {reason: "streak"|"stalled", weeks?, lifts?}`; `deloadWeight(top) -> number`; `deloadSets(sets) -> number`; `deloadAdvice({last, target, bw, hold}) -> null | {w?, r?, sets}`.
- Details: dates are `YYYY-MM-DD` that round-trip through `new Date`; `end` is kept only with a `start` and only when `end >= addDays(start, -1)`; the window is `start .. (end ?? addDays(start, 6))`; `day` = whole days since `start` plus 1; `suggestDeload` returns null while active, while `today <= dismissedUntil`, or while `today < addDays(start, 42)`; streak wins over stalled; `stalledLifts` groups sessions per lower-cased exercise name across workouts sorted by date, uses `workingSets`, skips entries with `bw === true` and workouts with `deload === true`, needs 4 sessions, stalled when `max(last 3 e1RM) <= 1.005 * max(earlier)`; `deloadWeight(top) = clamp(round(top * 0.9 / 2.5) * 2.5, 2.5, top)` (for `top < 2.5` return `top`); `deloadSets(n) = max(1, round(n * 0.6))`; `deloadAdvice` uses `workingSets(last)`; bodyweight/hold: `{sets: deloadSets(target.sets)}` when there are working sets; weighted: top = heaviest working weight (> 0), `w = deloadWeight(top)`, `r` = highest reps among sets at `top`, `sets = deloadSets(target.sets)`; no working sets or no weight: null.

  - `cleanDeload`: valid triple kept; `{start:"2026-02-30"}`, `"x"`, `5`, `null` -> dropped (a bad `start` also drops `end`); `end` before `start - 1` dropped; `end == start - 1` kept; non-objects give `{}`.
  - `activeDeload`: `start 2026-10-20` -> day 1 on the 20th, day 7 on the 26th, null on the 19th and the 27th; month boundary (`start 2026-10-28` is active on `2026-11-03`, day 7); `end 2026-10-22` ends it early (null on the 23rd); `end 2026-10-19` with `start 2026-10-20` is cancelled (null on the 20th); `{}`/undefined -> null.
  - `deloadDate`: same window logic independent of today; false for cancelled.
  - `suggestDeload`: streak 5 -> null, streak 6 -> `{reason:"streak", weeks:6}`; stalled 2 -> null, 3 -> `{reason:"stalled", lifts:3}`; both -> streak; active -> null; `dismissedUntil` equal to today -> null, yesterday -> allowed; last `start` 41 days ago -> null, 42 days ago -> allowed; junk deload ignored.
