# My Gym Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A person picks the equipment their gym has (preset, then adjust) and the exercise suggestions, type-ahead and Coach suggestions only offer exercises they can do; nothing already in their days or history is hidden.

**Architecture:** Pure logic (`GYM_PRESETS`, `gymFilter`, `gymCounts`) in `exercise-library.js`, unit-tested. The choice is `settings.gym` in the private settings doc (three places must carry it: snapshot parser, `store.saveSettings`, backup cleaner). `index.html` applies the filter in `suggestionsFor`, the type-ahead and Coach, and gets a My Gym screen plus a first-time hint card on the Days tab. No Firestore rules change.

**Tech Stack:** plain JS ES modules, `node --test`, headless Edge + Firebase-stub harness (`$TEMP/harness`, port 5071) for screenshots.

**Spec:** `docs/superpowers/specs/2026-10-19-my-gym-design.md` (binding; it holds the data shape, presets and screens, which this plan does not repeat).

## Global Constraints

- No new dependency, no build step, no new `public/*.js` file (so `APP_SHELL` does not change). `npm test` must keep passing with nothing installed.
- `index.html`, `lang-ar.js`, `sw.js` have CRLF endings: edit with Edit or Write-tool scripts (heredocs mangle backslashes and apostrophes).
- `settings.gym`: absent = not set (no filtering); `[]` = bodyweight only; only known `EQUIPMENT` ids, no duplicates. Rules for `users/{uid}/items/*` stay unchanged.
- Never hidden by the filter: names in `state.days`, in history (`exerciseNames()`), templates, backups, Lifts. Custom/unknown names (no equipment info) are always kept.
- Every new user-visible string goes through `t()`/`tn()` with an Arabic entry; equipment names already have Arabic (`nameOf("equipment", id)`).
- Bump `iron-log-v19` in the release task only. Nothing is deployed before the final review and the user's go-ahead.

## Review Focus

- `gym` surviving every round trip: `saveSettings` for `rest`/`seenBadges` must not erase it and the gym save must not erase them; the snapshot parser; backup export → restore → Task 2 tests (`cleanSettings`, plus a pure helper test for the settings write shape).
- `[]` (bodyweight only) acting differently from unset → Task 1 tests of `gymFilter`/`gymCounts`; Task 2 test that `[]` survives the cleaner.
- A person's own exercises vanishing after unticking equipment → Task 3 helper tests (history names kept in the type-ahead list).
- The "Hiding N" count not matching what is hidden → Task 3 helper test of `hiddenCount`.
- Taps swallowed while the checklist re-renders → Task 4 (re-render only on tap, no snapshot-driven redraw while the view is open; verified by screenshot run).

### Task 1: Gym logic in `public/exercise-library.js`

**Files:**
- Modify: `public/exercise-library.js`, `tests/exercise-library.test.js`

**Interfaces:**
- Produces (exported):
  - `GYM_PRESETS: [{id, name, equipment: string[]}]` in this order and with these ids: `bodyweight` "Bodyweight only" `[]`; `home` "Home" (`dumbbell, bench, pullup-bar, kettlebell, box, ab-wheel`); `basic` "Basic gym" (every `EQUIPMENT` item whose group is `weights` or `station`); `full` "Full gym" (all ids).
  - `gymFilter(names: string[], gym: string[]|undefined|null) → string[]`: `gym` not an array → `names` unchanged; else keep a name when `equipmentOf(name)` is `null` or every id is in `gym`; order preserved; unknown ids inside `gym` are harmless.
  - `gymCounts(gym) → {items, itemsTotal, exercises, exercisesTotal}`: `items` = number of distinct known ids in `gym`, `exercises` = `exercisesFor(gym).length`; totals = 39 and `EXERCISES.length`.
  - `sameGym(a, b) → boolean`: same set of ids regardless of order.
- Consumes: `EQUIPMENT`, `EXERCISES`, `equipmentOf`, `exercisesFor` (already in the file).

- [ ] **Step 1: Write the failing tests** in `tests/exercise-library.test.js`:
  - presets: ids/names unique, order as above, every id is in `EQUIPMENT`, `full.equipment.length === EQUIPMENT.length`, each preset's set is a subset of the next one's, `bodyweight.equipment` is `[]`.
  - `gymFilter(["Bench Press","Push-up","My Custom Lift"], undefined)` returns all three; with `[]` returns `["Push-up","My Custom Lift"]` (assuming Push-up needs nothing; assert with `equipmentOf` instead of hard-coding if unsure); with `["barbell","bench"]` keeps Bench Press and drops a machine exercise such as `"Pec Deck"` (use any name whose `equipmentOf` includes `pec-deck`); order preserved; `gym` containing `"nonsense"` is ignored.
  - `gymCounts([])`: `items 0`, `exercises` equals the number of library exercises with no equipment (20 today; assert against `EXERCISES.filter(e=>e.eq.length===0).length`); `gymCounts(all ids)`: `exercises === EXERCISES.length`; totals 39 / `EXERCISES.length`.
  - `sameGym(["a","b"],["b","a"])` true, `sameGym([],["a"])` false, `sameGym(undefined,[])` false.
- [ ] **Step 2: Run** `node --test tests/exercise-library.test.js` — Expected: FAIL (exports missing).
- [ ] **Step 3: Implement** the four exports in `exercise-library.js` as specified.

### Task 3: Applying the filter (suggestions, type-ahead, Coach)

**Interfaces:**
- Consumes: Task 1 `gymFilter`; Task 2 `state.settings.gym`.
- Produces:
  - `hiddenCount(lists: string[][], gym) → number` (exported, pure): total names across `lists` that `gymFilter` would drop (0 when `gym` is not an array).
  - `state.showAllGym` (session boolean, default false) and click action `gym-showall` (toggles, then redraws the current view).
